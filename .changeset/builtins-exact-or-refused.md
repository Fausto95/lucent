Make built-ins that silently differed from JavaScript behave as JavaScript does (`fromIndex`/`start`/`end` and `undefined` optional arguments, `split`'s limit, `$` patterns in `replace`, the name and message of `Error` classes, `Number.is*` and `Array.isArray` on unions, array lengths, numbers passed to narrower native integers, `toLocaleUpperCase`/`toLocaleLowerCase` following the device's locale), and throw `RangeError` for every element type when writing past an array's end or growing its `length`. Refuse what Lucent cannot match, including code that compiled before, naming what to use instead: `normalize()`, locale arguments, an error's `cause` and `Object.keys`/`values`/`entries` on object types (`LUCENT1003`), `for…in` (`LUCENT1009`) and `in` (`LUCENT1002`) on object types, `new Array(n)` unless `.fill(v)` follows it (to preallocate and assign each index, write `Array.from({ length: n }, (_, i) => …)`), `Array.from({ length: n })` without a map function unless the elements may be `undefined`, and `new Proxy`.
