Add typed native extensions. A Lucent package declares one in `lucent.json` (`extensions.<name>`): a C header in native sources both platforms build, the opaque structs Lucent code holds as handles (their create, destroy, methods and thread), what pointer parameters are (bytes with their length, a UTF-8 string, an error struct) and how results report failure. `lucent build` reads the header with clang, checks every name and shape against it, and fails naming the package and the field when they disagree. Lucent code, shared code included, imports the handles as classes and the functions by their C names from `lucent:ext/<name>`: handles close once (`close()`, `using`, or their last reference), throw `InvalidStateError` after, and cannot cross to JavaScript; a reported failure throws an Error with C's message and code; 64-bit integers are bigints; an exception escaping C ends the process at the call instead of unwinding through Lucent. The header must declare its functions in `extern "C"` for C++; a function taking a handle is bound only when the declaration names it; a `close()` from another thread waits for the calls using the handle. Editors get the declarations from `.lucent/native/types/ext/`.
