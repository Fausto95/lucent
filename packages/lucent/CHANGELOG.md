# @lucent-lang/lucent

## 0.3.0

### Minor Changes

- [#148](https://github.com/Fausto95/lucent/pull/148) [`d78cb50`](https://github.com/Fausto95/lucent/commit/d78cb50af99fc3dc7a5576ccd4d4b73e7e40972e) Thanks [@Fausto95](https://github.com/Fausto95)! - Give each package its own lock and thread (an actor) instead of one lock for all module code: modules that import one another share one, so a long job in one package no longer delays calls into another, or the main thread. The main thread never queues behind module jobs: `main(f)`, `present()` and `onAppEvent`/`onSceneEvent` listeners run once their package is free, and a delegate method that must answer waits only for the code holding the package then (debug builds log a wait over 50 ms). A JavaScript callback called synchronously from Lucent lets the main thread in meanwhile, which fixes a deadlock when that JavaScript waits for the main thread. A call across packages that would deadlock (two threads each holding one package and waiting for the other's) throws `Lucent: deadlock` instead of hanging. Native code that names `lucent::Scheduler` or the "legacy module context" now uses `lucent::Actor` (`Actor::shared()` for code of no package); generated code must be rebuilt (`lucent build`).

- [#167](https://github.com/Fausto95/lucent/pull/167) [`60c6bca`](https://github.com/Fausto95/lucent/commit/60c6bca43d48a3c9355272ca4ee53dbae88bb895) Thanks [@Fausto95](https://github.com/Fausto95)! - Add `adoptByteBuffer(buffer)` to `lucent:android`: a direct `ByteBuffer`'s bytes become a `NativeBuffer`, uncopied, which can move to a worker or, with `transferToArrayBuffer()`, to JavaScript, so a buffer an Android SDK fills reaches JavaScript with no copy. The Java buffer is kept reachable until the bytes are released; a heap or read-only buffer is a `TypeError`.

- [#216](https://github.com/Fausto95/lucent/pull/216) [`ce87e1f`](https://github.com/Fausto95/lucent/commit/ce87e1f712724d4a8977313627617ca51a25cf28) Thanks [@Fausto95](https://github.com/Fausto95)! - Adopt a camera or decoder frame as a `NativeBuffer` without copying it: `adoptPixelBuffer(pixelBuffer, plane?, access?)` from `lucent:ios` and `adoptHardwareBuffer(buffer, access?)` from `lucent:android` (Android 8 and later) lock the frame for the CPU until the buffer's bytes are released. With `"read"`, the default, the buffer is read-only: a write or `transferToArrayBuffer()` throws `InvalidStateError`. With `"readwrite"` it is writable and moves to JavaScript as an `ArrayBuffer`, uncopied.
