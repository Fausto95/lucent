## Your logic. Compiled, not interpreted.

Write it once in `*.lucent.ts`. The compiler handles the rest.

<div class="features not-content">
  <Feature title="A checked subset" icon="seti:typescript" href="/docs/reference/language/" link="Read the language">
    The real TypeScript checker in strict mode, then Lucent's own rules. Structs, unions, classes, closures, generics, async and errors behave as in JavaScript. Anything else is a stable LUCENT diagnostic at build time.
  </Feature>
  <Feature title="Native all the way" icon="rocket" href="/docs/how-it-works/" link="See the pipeline">
    C++20 with a small runtime, called through JSI from one pure C++ TurboModule. Sync calls return inline; async functions run off the JS thread and resolve on it.
  </Feature>
  <Feature title="Both platforms, both hosts" icon="puzzle" href="/docs/install/" link="Set it up">
    One source builds for iOS and Android, in bare React Native and in Expo. CocoaPods and CMake autolink it, and Metro swaps each import for a typed proxy.
  </Feature>
</div>

</ContainerSection>

## Make your next function native.

Add Lucent to a bare React Native or Expo app:

```sh title="terminal"
npm install -D @lucent-lang/lucent
npx lucent init
```

Requires Node 22.12+ and a development build (not Expo Go). [Full setup](/docs/install/)
