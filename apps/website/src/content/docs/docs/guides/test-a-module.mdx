<TabItem label="module">

```ts title="pace.lucent.ts"
import { error } from "lucent:core";

export type Split = { meters: number; seconds: number };

/** Seconds per kilometer over every split. */
export function pace(splits: Split[]): number {
  let meters = 0;
  let seconds = 0;
  for (const split of splits) {
    if (split.meters <= 0) throw error("E_BAD_SPLIT", `A split covers ${split.meters} m`);
    meters += split.meters;
    seconds += split.seconds;
  }
  if (meters === 0) throw error("E_NO_SPLITS", "No splits to average");
  return (seconds * 1000) / meters;
}
```

</TabItem>
<TabItem label="pace.test.ts">

```ts title="pace.test.ts"
import { expect, it } from "vitest";
import { pace } from "./pace.lucent";

it("averages over the whole distance", () => {
  expect(pace([{ meters: 1000, seconds: 300 }, { meters: 500, seconds: 165 }])).toBe(310);
});

it("rejects a run without splits", () => {
  expect(() => pace([])).toThrow(expect.objectContaining({ code: "E_NO_SPLITS" }));
});
```

A module is TypeScript, so the test runner imports it as it imports your other files. Only `lucent:core` needs a mapping, to `@lucent-lang/lucent/core`: its JavaScript version, installed with Lucent. Add the mapping to the config your app has, next to its preset.

With Jest, `it` and `expect` are globals, so leave out the `vitest` import.

## What runs in a test

- A shared module, and the shared modules it imports. `delay`, `error`, `compute` and the rest of [lucent:core](/docs/api/lucent-core/) run as JavaScript.
- `compute` runs its task on the test's thread, after a timer, with a copy of its input. In three cases its result differs from native code ([known limitations](/docs/releases/roadmap/#known-limitations)).
- A `NativeBuffer` lends a test its own bytes, where the app lends JavaScript a copy ([NativeBuffer](/docs/api/language/boundary/#nativebuffer)).
- `lucent:platform`, `lucent:thread` and the SDK modules have no JavaScript version. A module that imports one fails to load, so keep the logic you test in a shared module ([Share code between iOS and Android](/docs/guides/share-code-between-platforms/)).

A test checks the code as JavaScript runs it. Where native code differs from JavaScript ([Differences](/docs/api/language/differences/)), the test can't see it. [`lucent bench`](/docs/guides/measure-performance/) runs the same calls both ways and fails when their results differ.

## Test platform code in the app

Platform code runs only on iOS and Android. Call it from a screen of a development build, as [Run your first module](/docs/guides/first-module/) does. Check each platform's result on a simulator and an emulator.
