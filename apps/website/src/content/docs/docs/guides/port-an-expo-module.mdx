---
title: Port an Expo Module
description: Keep the TypeScript API, and write the Swift and Kotlin bodies as the two branches of one Lucent module.
kind: guide
---

import { Tabs, TabItem } from "@astrojs/starlight/components";

1. Copy the module's TypeScript API: its exported functions, types and enums. That's your module's export list.
2. For each function, take the Swift and the Kotlin body and write them as the two branches of one Lucent function, `if (PLATFORM === "ios") { … } else { … }`.
3. Keep the SDK calls; change the syntax. Swift's names work as they are, nested types join with `_`, and Kotlin's getters are properties.
4. Replace `AsyncFunction(…).runOnQueue(.main)` with an `async` function whose SDK calls sit in `main()`.
5. Replace `throw Exception(…)` with `throw error("ERR_CODE", message)`, keeping the original's codes, so JavaScript can test them.
6. Replace events (`sendEvent`) with a callback parameter and a stop function. See [Send events to JavaScript](/docs/guides/send-events-to-javascript/).
7. Delete the Swift, the Kotlin, the podspec, the Gradle file and `expo-module.config.json`. Point the JavaScript imports at the `.lucent` module.

<TabItem label="Expo Module (Swift)">

```swift title="ClipboardModule.swift"
AsyncFunction("hasStringAsync") { () -> Bool in
  UIPasteboard.general.hasStrings
}
```

<TabItem label="Lucent">

```ts title="clipboard.lucent.ts"
import { PLATFORM } from "lucent:platform";
import { UIPasteboard } from "lucent:ios/UIKit";
import { ClipboardManager, ClipDescription } from "lucent:android/android.content";
import { appContext } from "lucent:android";
import { main } from "lucent:thread";

export async function hasStringAsync(): Promise<boolean> {
  if (PLATFORM === "ios") {
    return UIPasteboard.general.hasStrings;
  } else {
    return main(() => {
      const manager = appContext().getSystemService(ClipboardManager);
      return manager?.getPrimaryClipDescription()?.hasMimeType(ClipDescription.MIMETYPE_TEXT_PLAIN) ?? false;
    });
  }
}
```

</TabItem>
</Tabs>

Test the port next to the original: call both from one screen and compare. The [examples](/docs/examples/) are ports of six Expo and community modules, each checked this way.

:::caution
Some SDK features aren't bound yet, such as Swift-only APIs, Android generic classes' members and iOS subclassing. [SDK types](/docs/reference/platform-types/#not-bound-yet) lists them; check before you start.
:::
