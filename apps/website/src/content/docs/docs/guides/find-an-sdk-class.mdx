```sh title="terminal" nocopy
$ npx lucent sdk search FeedbackGenerator

searched 191 modules (your imports and the SDK cache; lucent sdk prefetch --all to search every module)
```

The search lists the classes and members whose name contains the term, by platform and module. A class's row ends with the import to copy, and a member's row names its class.

It searches the modules your code imports and those in the SDK cache. To search the whole SDK, run `npx lucent sdk prefetch --all` once: it caches every module, which takes minutes.

## See the declaration

```sh title="terminal" nocopy
$ npx lucent sdk show UIKit.UIImpactFeedbackGenerator
// lucent:ios/UIKit
/**
 * Main thread only: use it inside `main(() => …)` from lucent:thread.
 * Since iOS 10.0.
 */
export declare class UIImpactFeedbackGenerator extends UIFeedbackGenerator {
  private readonly __lucent_UIImpactFeedbackGenerator: never;
  constructor(style: UIImpactFeedbackGenerator_FeedbackStyle);
  impactOccurred(): void;
  /** Since iOS 17.5. */
  impactOccurred(location: CGPoint): void;
  /** Since iOS 13.0. */
  impactOccurred(intensity: number): void;
  /** Since iOS 17.5. */
  impactOccurred(intensity: number, location: CGPoint): void;
}
```

Name a type as `<Module>.<Type>`: `UIKit.UIImpactFeedbackGenerator`, or `android.os.Vibrator` for an Android class. You get the declaration your code is checked against, with its doc comments:

- `Main thread only` means calling it in code the main thread runs, such as a `main()` function.
- `Since iOS 17.5.` or `Since API 26.` is the version that added it. One newer than the oldest OS your app runs on needs a [version check](/docs/guides/check-the-os-version/).

Add a member, as in `UIKit.UIImpactFeedbackGenerator.impactOccurred`, to print only its overloads, without their doc comments.

## Read it in your editor

`lucent build` writes the declarations of the modules your code imports to `.lucent/native/types/`, and maps `lucent:*` to them in the app's `tsconfig.json`. Your editor then completes SDK names, and hovering one shows its declaration and doc comments.

## When a member isn't there

```sh title="terminal" nocopy
$ npx lucent sdk show LocalAuthentication.LADomainStateCompanion
// lucent:ios/LocalAuthentication
/**
 * Since iOS 18.0.
 */
export declare class LADomainStateCompanion extends NSObject {
  private readonly __lucent_LADomainStateCompanion: never;
  constructor();
  /** Lucent cannot use this yet: set values cannot cross to Swift yet. */
  readonly availableCompanionTypes: Set<LACompanionType>;
  readonly stateHash: Uint8Array | null;
  stateHashFor(companionType: LACompanionType): Uint8Array | null;
}
```

A member Lucent can't use yet is declared with the reason in its doc comment, and using it fails to compile with that reason. A member Lucent couldn't type isn't declared at all. `lucent sdk coverage --members` lists both, with every other member of the module and how far each gets:

```sh title="terminal" nocopy
$ npx lucent sdk coverage --ios LocalAuthentication --members | grep availableCompanionTypes
  discovered     LADomainStateCompanion.availableCompanionTypes                 set values cannot cross to Swift yet
```

A member that stops at `discovered` can't be called, for the reason given. [What isn't bound](/docs/api/ios-sdk/#what-isnt-bound) defines the stages, and `--android <packages>` measures Android packages instead.

To use one now, wrap it in your own Swift, in a local pod, or your own Kotlin, in a Gradle module. The roadmap lists the [known limitations](/docs/releases/roadmap/#known-limitations).
