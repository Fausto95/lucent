```ts title="contacts.lucent.ts"
import { delay } from "lucent:core";

const byInitial = new Map<string, string[]>();

/** Async: runs on the Lucent thread, so the JS thread stays free. */
export async function index(names: string[]): Promise<number> {
  for (let i = 0; i < names.length; i++) {
    const name = names[i]!;
    const initial = name.charAt(0).toLowerCase();
    const group = byInitial.get(initial);
    if (group) group.push(name);
    else byInitial.set(initial, [name]);
    if (i % 1000 === 999) await delay(0); // ends the turn: a waiting search() runs now
  }
  return names.length;
}

/** Synchronous: runs on the JS thread, which waits for the result. */
export function search(prefix: string): string[] {
  const lower = prefix.toLowerCase();
  const group = byInitial.get(lower.charAt(0)) ?? [];
  return group.filter((name) => name.toLowerCase().startsWith(lower));
}
```

<TabItem label="App.tsx">

```tsx title="App.tsx"
import { useEffect, useState } from "react";
import { Text, TextInput, View } from "react-native";
import { index, search } from "./src/contacts.lucent";
import names from "./names.json";

export default function App() {
  const [query, setQuery] = useState("");
  const [count, setCount] = useState(0);

  useEffect(() => {
    void index(names).then(setCount); // returns before the indexing runs
  }, []);

  return (
    <View>
      <Text>{count} contacts</Text>
      <TextInput value={query} onChangeText={setQuery} placeholder="Search" />
      <Text>{query ? search(query).join("\n") : ""}</Text>
    </View>
  );
}
```

`index` is `async`, so it runs on the Lucent thread, a background thread, from its first line. Its arguments are checked and copied on the JS thread first, and its promise settles there. The `async` methods of an exported class run the same way.

`search` is synchronous: it runs on the JS thread while JavaScript waits. Keep synchronous exports quick, since JavaScript can do nothing else until they return.

## Let waiting calls in

Module code runs one turn at a time, under the Lucent lock. A turn lasts until an `await` has to wait, so without its `delay(0)`, `index` would be one long turn. Until a turn ends, these calls from JavaScript wait for it, and the JS thread waits with them:

- a synchronous call, such as `search()`;
- an async call, whose arguments are checked holding the lock before it returns its promise;
- `abort()` on a signal JavaScript passed to the module.

`await delay(0)` from [lucent:core](/docs/api/lucent-core/#delay) ends the turn, so the calls waiting run before the loop goes on. `await delay(ms)` waits `ms` milliseconds without holding the lock. [The Lucent lock](/docs/api/language/concurrency/#the-lucent-lock) has the rules.

:::note
An export that returns a `Promise` without being `async` runs on the JS thread until it returns. Mark it `async` to move its work off.
:::

Work that keeps a CPU busy for long belongs on worker threads, which don't take the lock: [Run heavy work in parallel](/docs/guides/run-in-parallel/).
