import { UIColor, UIFont, UILabel, type UIView } from "lucent:ios/UIKit";
import { Flex } from "lucent:ui";
import type { PedometerProps } from "./pedometer.lucent";

export function Pedometer(props: PedometerProps): UIView {
  return (
    <Flex style={{ flexDirection: "row", alignItems: "center", gap: 8 }}>
      <UILabel text="Steps today" textColor={UIColor.secondaryLabel} layout={{ flexGrow: 1 }} />
      <UILabel text={`${props.steps}`} font={UIFont.boldSystemFont(28)} />
      {props.steps >= 10000 && <UILabel text="Goal" />}
    </Flex>
  );
}

A tag is a view class: any class that extends `UIView` or Android's `View`, from the SDK or a library Lucent binds. The declaration file declares the props once, and each platform file returns its own views.

- An attribute is a writable property on iOS, and a one-value setter on Android: `text` calls `setText` ([Props](/docs/api/views/platform-views/#props)).
- An attribute that reads a prop, as the second label's `text` reads `props.steps`, is set again when React passes a new value.
- Listeners and control events are `on…` attributes, such as a `UISwitch`'s `onValueChanged` ([Events](/docs/api/views/platform-views/#events)).
- `{cond && <X />}` adds a child while the condition holds, and `items.map` with a `key` makes a list ([Children](/docs/api/views/platform-views/#children)).
- `Flex` lays out its children with React Native's Yoga, and `layout` places one child ([Layout](/docs/api/views/platform-views/#layout)).

A plain `UIView` or `ViewGroup` doesn't lay out its children, so put them in a `Flex` or a native container. A component whose root is a `Flex` is sized by its content when its style gives no size.

`tsc` checks a `.lucent.tsx` file's JSX as React's and reports errors in it: only the [editor plugin](/docs/api/integrations/#jsx-in-lucenttsx-files) types it.

[UIKit and Android views in JSX](/docs/api/views/platform-views/) gives every rule, and how to list a module's tags.

## Write it as one file

A component fits in one file too: each `PLATFORM` branch returns its platform's views, and only that platform compiles its branch.

```tsx title="step-count.lucent.tsx"
import { PLATFORM } from "lucent:platform";
import { TextView } from "lucent:android/android.widget";
import { UILabel } from "lucent:ios/UIKit";

export function StepCount(props: { steps: number }) {
  if (PLATFORM === "ios") return <UILabel text={`${props.steps} steps`} />;

  return <TextView text={`${props.steps} steps`} />;
}
```

Platform files suit components whose platforms share little code, or whose commands differ: `expose()` can't stand in a branch. A one-file component leaves its return type out ([One file or platform files](/docs/api/views/components/#one-file-or-platform-files)).
