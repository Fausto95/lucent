```ts title="downloads.lucent.ts"
import { delay, EventEmitter } from "lucent:core";

export type Progress = { url: string; percent: number };

export const downloads = new EventEmitter<{
  progress: (progress: Progress) => void;
  done: (url: string) => void;
}>();

export async function download(url: string): Promise<void> {
  for (let percent = 0; percent <= 100; percent += 10) {
    downloads.emit("progress", { url, percent });
    await delay(200); // stand-in for the network
  }
  downloads.emit("done", url);
}
```

<TabItem label="JS usage">

```tsx title="App.tsx"
import { useEffect, useState } from "react";
import { Button, Text, View } from "react-native";
import { type Progress, download, downloads } from "./src/downloads.lucent";

export default function App() {
  const [progress, setProgress] = useState<Progress>();

  useEffect(() => {
    const subscription = downloads.addListener("progress", setProgress);
    return () => subscription.remove();
  }, []);

  return (
    <View>
      <Button title="Download" onPress={() => download("https://example.com/a.zip")} />
      <Text>{progress ? `${progress.url}: ${progress.percent}%` : "Idle"}</Text>
    </View>
  );
}
```

The type argument names each event and its listener's signature, as Expo's `EventEmitter` does. `emit(name, ...args)` calls the event's listeners in the order they were added.

- JavaScript gets the same object each time, with `addListener`, `emit`, `listenerCount` and `removeAllListeners`. Naming an event the type doesn't declare throws a `TypeError`.
- Each value reaches JavaScript as a copy, posted to the JS thread, so a listener's throw is only logged ([Call a JavaScript callback](/docs/guides/accept-a-js-callback/)). During a synchronous call from JavaScript, its listeners run at once.
- A reload removes JavaScript's listeners, and `listenerCount` stops counting them. So a module can start an SDK listener while the count is above 0.
- In Lucent, an event's name is a string literal, and Lucent code may add listeners too.

The full contract is on [lucent:core](/docs/api/lucent-core/#eventemitter).

## A stream for one caller

For a stream that one caller starts and stops, export an async function that takes a callback and an `AbortSignal`, and pass both to [subscribe()](/docs/api/lucent-core/#subscribe). Its `register` adds the listener and returns the cleanup that removes it. JavaScript's `abort()` ends the stream: the cleanup runs once, and the promise resolves.

[Implement an SDK delegate or listener](/docs/guides/implement-a-delegate/) uses one. For one value rather than a stream, see [Turn a callback API into a promise](/docs/guides/await-a-callback-api/).
