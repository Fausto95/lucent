A native extension binds a C header a package ships. [Wrap a C library](/docs/packages/wrap-a-c-library/) shows a whole one; this page holds the rules.

## Fields

| Field | Type | Required | Meaning |
| --- | --- | --- | --- |
| `extensions.<name>.header` | `string` | yes | The C header, relative to the package. Its directory is in both ios.nativeSources and android.nativeSources, so both builds compile the extension and search there. It must compile as C and as C++, declaring its functions in extern "C" when C++ includes it. Functions that take only numbers and booleans are bound as they are; one that takes a handle must be named here. |
| `extensions.<name>.handles` | `{ [name]: object }` |  | Opaque struct (declared, not defined, in the header) → the handle Lucent code holds, a class of lucent:ext/\<name\>. Handles cannot cross the JavaScript boundary: a Lucent class keeps one. |
| `extensions.<name>.handles.<name>.create` | `string` | yes | The function that makes one: it returns a pointer to the struct, null when it fails (declare failsWhen: null). It is the class's constructor. |
| `extensions.<name>.handles.<name>.destroy` | `string` | yes | void f(T \*): runs once, when the handle closes (close(), a using declaration, or its last reference going). |
| `extensions.<name>.handles.<name>.methods` | `{ [name]: string }` |  | Method name → the function it calls, with the handle as its first argument. |
| `extensions.<name>.handles.<name>.affinity` | `"any" or "main"` |  | The thread: any, one call at a time (the default), or the main thread, where Lucent code uses it inside main(() =\> …). |
| `extensions.<name>.functions` | `{ [name]: object }` |  | C function name → what its parameters and result mean. |
| `extensions.<name>.functions.<name>.params` | `{ [name]: object }` |  | C parameter name → what the pointer is. Numbers, booleans and handles need nothing; nothing escapes the call. |
| `extensions.<name>.functions.<name>.params.<name>.bytes` | `"read" or "write"` | yes |  |
| `extensions.<name>.functions.<name>.params.<name>.length` | `string` | yes | The integer parameter holding the byte count: Lucent passes the array's length. |
| `extensions.<name>.functions.<name>.params.<name>.string` | `"utf8"` | yes |  |
| `extensions.<name>.functions.<name>.params.<name>.error` | `string` | yes | A struct declared in errors. |
| `extensions.<name>.functions.<name>.failsWhen` | `"null" or "negative" or "nonzero" or "zero" or "false"` |  | How the result says the call failed, which throws an Error with the error struct's message and code. With nonzero or false the result is a status, and the Lucent function returns nothing. |
| `extensions.<name>.functions.<name>.affinity` | `"any" or "main"` |  | The thread: any, one call at a time (the default), or the main thread, where Lucent code uses it inside main(() =\> …). |
| `extensions.<name>.functions.<name>.blocking` | `boolean` |  | It may block (I/O, locks, long work): calling it inside main(() =\> …) is a warning. |
| `extensions.<name>.errors` | `{ [name]: object }` |  | C struct name (defined in the header) → the error its functions fill in. |
| `extensions.<name>.errors.<name>.code` | `string` |  | An integer field: the Error's code. |
| `extensions.<name>.errors.<name>.message` | `string` | yes | A const char \* field: the Error's message, copied before the call returns. |
| `extensions.<name>.errors.<name>.release` | `string` |  | void f(E \*), called after every call that takes the struct, once it was read, when it holds something to free. |

## What Lucent code gets

- Each handle becomes a class of `lucent:ext/<name>`: `create` is its constructor, and `methods` are its methods.
- `close()` and `[Symbol.dispose]()` destroy a handle once, and so does its last reference going. A use after that throws an `InvalidStateError`.
- Integers wider than 32 bits (`long`, `size_t`, `int64_t` and their unsigned forms) are bigints. Other integers are numbers, checked on the way in as WebIDL's `[EnforceRange]` does.
- A handle can't cross to JavaScript ([LUCENT2006](/docs/api/diagnostics/#lucent2006)): a Lucent class keeps it and publishes what JavaScript needs.
- The declarations editors read are written to `.lucent/native/types/ext/<name>.d.ts`.

## How the header is read

- The header lives in a directory both `ios.nativeSources` and `android.nativeSources` list. It compiles as C and as C++, declaring its functions in `extern "C"` when C++ includes it.
- `lucent build` reads it with clang: `$LUCENT_CLANG`, else `clang` on the `PATH`, else Xcode's, else the newest Android NDK's.
- A name or shape the declaration uses that the header doesn't have fails the build, naming the field.
- A function whose parameters are only numbers and booleans is bound without a declaration. One that takes a handle must be named, in `functions` or as a method.
- A callback, a variadic function or a struct passed by value can't be bound. The generated declarations list each one at the end, with the reason.

## Errors and threads

- A call whose `failsWhen` holds throws an Error with the error struct's message and code.
- An exception escaping the C or C++ code ends the process: catch it in the C++ and report it through the error struct.
- A call holds its handles: a `close()` from another thread while it runs destroys the handle when the call returns.
- Extension calls can't be cancelled ([known limitations](/docs/releases/roadmap/#known-limitations)).
