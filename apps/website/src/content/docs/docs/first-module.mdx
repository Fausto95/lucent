import { Tabs, TabItem, Steps } from "@astrojs/starlight/components";

<Steps>

1. ### Write the module

   ```ts title="greet.lucent.ts" cpp
   export function greet(name: string): string {
     const trimmed = name.trim();
     return trimmed.length > 0 ? `Hello, ${trimmed}!` : "Hello, stranger!";
   }
   ```

   Save it as `src/greet.lucent.ts`. Any `*.lucent.ts` file is a module, and its exports are what JavaScript can call.

2. ### Call it from a screen

   ```tsx title="App.tsx"
   import { Text } from "react-native";
   import { greet } from "./src/greet.lucent";

   export default function App() {
     return <Text>{greet("  Ada ")}</Text>;
   }
   ```

   The import is typed from the source, so your editor checks the call.

3. ### Run the app

   <Tabs syncKey="setup">
   <TabItem label="Expo">

   ```sh title="terminal"
   npx expo run:ios
   ```

   The config plugin builds your modules during prebuild. Xcode then compiles the C++ into the app.

   </TabItem>
   <TabItem label="Bare React Native">

   ```sh title="terminal"
   npx lucent build
   cd ios && pod install && cd ..
   npx react-native run-ios
   ```

   On Android, skip the first two lines: the Gradle task runs `lucent build` itself.

   </TabItem>
   </Tabs>

   The screen shows `Hello, Ada!`, computed in C++.

4. ### Change it

   Change `Hello` to `Hi` and save. While Metro runs, `lucent dev` rebuilds the native package and prints one line in Metro's output:

   ```sh title="terminal" nocopy
   [14:02:11] ✓ 2 modules  36 ms · rebuild the app
   ```

   The C++ is part of the app binary, so reloading JavaScript doesn't replace it. Run the app again to see `Hi, Ada!`.

5. ### Read an error

   Change the parameter to `name: any` and save:

   ```sh title="terminal" nocopy
   [14:03:40] ✗ 1 error
     src/greet.lucent.ts:1:23  LUCENT2001  `any` has no native representation; give this value a concrete type
       fix: use a concrete type, a union, or a generic parameter
   ```

   Each error has a code, a place and a fix. `npx lucent explain LUCENT2001` shows why the rule exists, with a wrong and a right example. Put `string` back.

</Steps>

## What happened

1. The TypeScript checker checked `greet.lucent.ts` against Lucent's rules.
2. Lucent compiled it to C++ and wrote the native package to `.lucent/native`.
3. Xcode or Gradle compiled the native package into your app.
4. Metro replaced the `greet.lucent` import with a proxy.
5. Calling `greet` went through JSI to the C++ and back.

[How Lucent works](/docs/how-it-works/) follows each step.
