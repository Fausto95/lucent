This page names the page that holds the exact rules of each import, language feature, command, file and error. Find what you're looking at in a table below, and follow its link. The guides show these rules in use, and link back here.

## Imports in a module

| Import | What it gives | Page |
| --- | --- | --- |
| `lucent:core` | `delay`, `now`, errors with a code, UTF-8, `fromCallback`, `subscribe`, `compute` and `NativeBuffer` | [lucent:core](/docs/api/lucent-core/) |
| `lucent:platform` | `PLATFORM`, the platform the code runs on | [lucent:platform](/docs/api/lucent-platform/) |
| `lucent:thread` | `main()`, which runs a function on the main thread | [lucent:thread](/docs/api/lucent-thread/) |
| `lucent:ios` | iOS helpers: `available`, `Out`, `mainQueue`, the `as*` readers, `present`, app and scene events | [lucent:ios](/docs/api/lucent-ios/) |
| `lucent:ios/<Module>` | An iOS SDK framework, a pod's module, or a framework a Lucent package ships | [iOS SDK bindings](/docs/api/ios-sdk/) |
| `lucent:android` | Android helpers: `appContext`, `available`, `currentActivity`, activity results, permissions, Activity events | [lucent:android](/docs/api/lucent-android/) |
| `lucent:android/<package>` | A package of the Android SDK, of the app's Gradle libraries, or of a library a Lucent package ships | [Android SDK bindings](/docs/api/android-sdk/) |
| `lucent:ext/<name>` | A C header a package ships as a native extension, a C++ library through a C interface | [Native extensions](/docs/packages/native-extensions/) |
| `console`, `AbortController`, `AbortSignal` | The globals every module has, without an import | [Globals](/docs/api/globals/) |
| `./other.lucent` | Another module of the app | [Modules](/docs/api/language/modules/) |
| `<package>/<path>.lucent` | A module of a Lucent package the app depends on, by its path in the package | [Modules](/docs/api/language/modules/) |

Views are experimental, behind `LUCENT_VIEWS=fabric`. Their modules and rules have pages of their own:

| Import or code | What it gives | Page |
| --- | --- | --- |
| `lucent:ui` | What a component's setup uses: signals, effects, commands, children | [lucent:ui](/docs/api/views/lucent-ui/) |
| `lucent:compose` | Jetpack Compose, for a component's content on Android | [lucent:compose](/docs/api/views/lucent-compose/) |
| `lucent:swiftui` | SwiftUI, for a component's content on iOS | [SwiftUI and Compose in JSX](/docs/api/views/swiftui-and-compose/) |
| `*.lucent.tsx` | A component: its props, `on…` events and `expose()` commands | [Components](/docs/api/views/components/) |
| `<UILabel>`, `<TextView>` | UIKit and Android views as JSX tags, on `main` and not in 0.1.2 | [UIKit and Android views](/docs/api/views/platform-views/) |

## Entry points of @lucent-lang/lucent

`@lucent-lang/lucent` is the one package an app installs. Modules don't import it: they import `lucent:*`, which the compiler provides. The app's tools use these entry points:

| Entry point | What it is | Where it goes |
| --- | --- | --- |
| `@lucent-lang/lucent` | The Expo config plugin, the package's main export | `"plugins"` in `app.json` |
| `@lucent-lang/lucent/app.plugin.js` | The same plugin, under the file name Expo looks for | Expo resolves it |
| `@lucent-lang/lucent/metro` | `withLucent(config, options?)`, which makes Metro bundle each module's proxy | `metro.config.js` |
| `@lucent-lang/lucent/ts-plugin` | The TypeScript plugin that shows Lucent's diagnostics in the editor | `"plugins"` in the `compilerOptions` of `tsconfig.json` |
| `@lucent-lang/lucent/core` | `lucent:core` written in JavaScript and typed as `lucent:core`, for tests that run modules as plain TypeScript | Jest's `moduleNameMapper`, or Vitest's `alias` |
| `@lucent-lang/lucent/package.json` | The package manifest, through which Lucent's Gradle task finds the package | `android/app/build.gradle` |
| `lucent` | The command-line tool | `npx lucent`, or a script in the app's package.json |

[Integrations](/docs/api/integrations/) gives the options of the Expo plugin, `withLucent` and the editor plugin. [Test a module](/docs/guides/test-a-module/) sets up `@lucent-lang/lucent/core`.
