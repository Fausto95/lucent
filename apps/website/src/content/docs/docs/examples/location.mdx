title: Location
description: "`expo-location`'s API on CoreLocation and Android's `LocationManager`: permission, current position, and positions sent to JavaScript as they arrive."
kind: example
---

- iOS: `Updates` implements `CLLocationManagerDelegate`. The managers are made on the main thread with `main()`, since they deliver to the thread that made them.
- Android: the current position is Play services' fused location, a `Task` whose completion listener `fromCallback` turns into a promise. Watching uses a plain function as the `LocationListener`, and `removeUpdates` takes the same function back.
- `watchPositionAsync` sends each position to a JS callback until `stopWatching(id)`.
- Android's location permissions reach the app's manifest by themselves: the SDK marks `requestLocationUpdates` with them.

```tsx title="App.tsx"
import * as Location from "./src/location.lucent";

const here = await Location.getCurrentPositionAsync();
console.log(here.coords.latitude, here.coords.longitude);

const id = await Location.watchPositionAsync((position) => {
  console.log(position.coords.latitude, position.coords.longitude);
});
await Location.stopWatching(id);
```

:::caution
The port reads the permission but doesn't ask for it. Ask with `PermissionsAndroid` or `expo-location`, and add `NSLocationWhenInUseUsageDescription` to `Info.plist`.
:::

The current position comes from Play services, as in expo-location, so the app depends on `play-services-location` (the example apps do). Source: [location.lucent.ts](https://github.com/Fausto95/lucent/blob/main/scripts/example-app/src/sdk/location.lucent.ts).
