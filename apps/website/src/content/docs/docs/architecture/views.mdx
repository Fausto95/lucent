```tsx title="ticker.lucent.tsx"
import { appContext } from "lucent:android";
import { TimeAnimator } from "lucent:android/android.animation";
import { TextView } from "lucent:android/android.widget";
import { Timer } from "lucent:ios/Foundation";
import { UILabel } from "lucent:ios/UIKit";
import { PLATFORM } from "lucent:platform";
import { effect, expose, onDispose, signal } from "lucent:ui";

export function Ticker(props: { label: string; onTick?: (count: number) => void }) {
  const count = signal(0);
  const tick = () => {
    count.set(count.peek() + 1);
    props.onTick?.(count.peek());
  };

  expose({ reset: () => count.set(0) });

  if (PLATFORM === "ios") {
    const label = new UILabel();
    const timer = Timer.scheduledTimer(1, true, () => tick());

    onDispose(() => timer.invalidate());
    effect(() => {
      label.text = `${props.label}: ${count.get()}`;
    });

    return label;
  }

  const text = new TextView(appContext());
  const animator = new TimeAnimator();
  let last = Date.now();

  animator.setTimeListener((_animation, _total, _delta) => {
    if (Date.now() - last < 1000) return;

    last = Date.now();
    tick();
  });
  animator.start();
  onDispose(() => {
    animator.setTimeListener(null);
    animator.cancel();
  });
  effect(() => {
    text.setText(`${props.label}: ${count.get()}`);
  });

  return text;
}
```

import { useRef } from "react";

export default function App() {
  const ticker = useRef<TickerRef>(null);

    <View>
      <Ticker ref={ticker} label="Uptime" onTick={(count) => console.log(count)} />
      <Button title="Reset" onPress={() => ticker.current?.reset()} />
    </View>
  );
}

## A component is a Fabric component

An exported function of a `.lucent.tsx` module that returns a view is a component. `lucent build` generates the props, events, shadow node and descriptor Fabric needs for each.

Its proxy exports a React component: props are React props, events are callback props, and the [commands](/docs/api/views/components/#commands-and-requests) setup passes to [`expose`](/docs/api/views/lucent-ui/#expose) are its ref's methods.

## Setup runs once per mount

A mount is one run of setup on one native host view, while that view shows the component.

- **Create.** The first commit runs setup, and the view it returns becomes the host's content.
- **Update.** A later commit hands over the changed props at once, and the effects that read a changed prop or signal run again.
- **Dispose.** When the view goes, its effects stop and its `onDispose` cleanups run.
- **Recycle.** iOS always pools views; Android does only with React Native's `enableViewRecycling` on. Recycling disposes the mount, and the next commit runs setup again ([Mounts and recycling](/docs/api/views/components/#mounts-and-recycling)).
- **Reload.** React Native drops the old views, disposing their mounts, and mounts new ones.

## The main thread, without the lock

Setup, effects, commands and the callbacks setup gives the platform run on the main thread, in the [main context](/docs/api/language/concurrency/#the-main-context). It never takes the Lucent lock, so a view never waits behind module code, and can't read module state ([LUCENT3022](/docs/api/diagnostics/#lucent3022)).

An event prop's call is posted to the JavaScript thread, so a view never waits for JavaScript.

## SwiftUI and Compose bodies

A component can return JSX from `lucent:swiftui` or `lucent:compose` instead of a view. The body becomes a Swift `View` in a `UIHostingController`, or a `@Composable` in a `ComposeView`, one per mount.

The setup still compiles to C++: it computes the values the body reads and pushes each change into its state. Functions the body calls run Lucent code.

## Sizing and children

A component whose style gives it a size, explicit or from flex, fills it. One taking children is sized by Yoga, as a View is, never by its content.

Otherwise the host measures its content on the main thread whenever the mount's code has run. Code after an `await` calls [`invalidateSize()`](/docs/api/views/lucent-ui/#invalidatesize) instead.

A component whose props declare `children?: Children` puts a [`slot()`](/docs/api/views/lucent-ui/#slot) view where its children go. React Native owns the children and their frames, and setup decides where the slot sits ([Put React children inside a native view](/docs/guides/views/children/)).

## Limits

Beside Lucent's other [known limitations](/docs/releases/roadmap/#known-limitations):

- Views have run only on simulators and emulators. Unchecked: SwiftUI hosting on iOS 17 and earlier, Compose under rotation, react-native-screens, and TalkBack.
- Long work in setup, effects or commands stalls the UI: move it to a [compute task](/docs/guides/run-in-parallel/).
- A size measured from content, and a slot's place, wait for the JavaScript thread to apply them. Until then the view keeps its last layout, zero-sized at mount.
- A fixed-size slot inside a component sized by its children gets three reports to settle its place, then stops.
- An absolutely positioned child is placed from the slot, grown by the component's padding, as a View's child is from its padding box.
- The React children share one slot, so a stack view can't arrange each one itself.
- A transform on a view between the host and the slot applies to the children, but their layout ignores it.
- A slot inside a native scroll view doesn't scroll: put a React `ScrollView` in the slot. `removeClippedSubviews` doesn't apply to its children.
- Only a `Coalesced` event drops all but its latest value: the others queue while JavaScript is busy ([Delivery](/docs/api/views/components/#delivery)).
- With two React Native runtimes alive, requests are answered to the one that connected last.
- Helper view functions take plain data, and callbacks of numbers, booleans and strings: no toolkit values, children, lists or bindings.
- SwiftUI: a static value named like a method, such as `Animation.easeInOut`, is left out: call the method. Only closed ranges (`a...b`) map, and content conditions must be `boolean`. `Int(x)` traps on NaN or infinity, and a two-value `onChange` closure doesn't type-check.
- Compose: when two Kotlin packages declare a class of the same name, `lucent:compose` keeps the first one's.
- [Platform-view JSX](/docs/api/views/platform-views/): only a `Flex` lays out a plain view's children, and a stack view's Auto Layout sees no size for a `Flex`. Android's `AdapterView` declares `addView(View, int)` but throws from it.
- Platform-view JSX: a view made through a Swift initializer needs `create`. A pod's view inherits `UIView`'s initializers only once a file imports `lucent:ios/UIKit`, even with a bare `import`.
- A listener with several methods, such as `TextWatcher` or SeekBar's, is left out of JSX, and setup can't give one ([LUCENT3021](/docs/api/diagnostics/#lucent3021)).
