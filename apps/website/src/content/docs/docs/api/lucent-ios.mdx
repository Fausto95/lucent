The iOS SDK itself is imported from `lucent:ios/<Framework>`, typed from the installed Xcode. [iOS SDK bindings](/docs/api/ios-sdk/) gives the rules, and [Find an SDK class](/docs/guides/find-an-sdk-class/) looks one up.

## Example

```ts title="haptic.lucent.ts"
import { PLATFORM } from "lucent:platform";
import { UIImpactFeedbackGenerator, UIImpactFeedbackGenerator_FeedbackStyle as Style } from "lucent:ios/UIKit";
import { available } from "lucent:ios";
import { main } from "lucent:thread";

export async function tap(): Promise<void> {
  if (PLATFORM === "ios") {
    await main(() => {
      const style = available("ios", 13) ? Style.soft : Style.light;
      new UIImpactFeedbackGenerator(style).impactOccurred();
    });
  }
}
```

### retainedHandle()

```ts title="ios.d.ts"
function retainedHandle(object: NSObject): NativeHandle;
```

A handle native code reads: the object's address, retained (+1) until the handle is released, then released once. A library that takes an `id` or a CF type, such as a frame processor taking a CVPixelBufferRef, gets `pointer`; JavaScript gets the same handle. Release it, from either side, once the library is done.

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `object` | `NSObject` | yes | The object to hold: a nil one is a TypeError. |

```ts title="retainedHandle.lucent.ts"
import { type NSObject, retainedHandle } from "lucent:ios";
import type { NativeHandle } from "lucent:core";

// A camera frame's CVPixelBuffer, as a sample buffer delegate gets it.
function forSkia(pixelBuffer: NSObject): NativeHandle {
  return retainedHandle(pixelBuffer);
}
```

### withPixelBytes()

```ts title="ios.d.ts"
function withPixelBytes<R>(
  pixelBuffer: NSObject,
  f: (bytes: Uint8Array, bytesPerRow: number, width: number, height: number) => R,
  plane?: number,
): R;
```

Calls `f` with a CVPixelBuffer's bytes, locked for reading while it runs. The lock is `CVPixelBufferLockBaseAddress` with `kCVPixelBufferLock_ReadOnly`, released after `f`, also when it throws. `f` gets the plane's bytes, its row stride (`bytesPerRow`), width and height.

For a planar format (YUV), the plane is the one given; otherwise plane 0. The bytes are copied once, under the lock, so they stay valid after `f` returns. The buffer itself is locked only while `f` runs.

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `pixelBuffer` | `NSObject` | yes | A CVPixelBuffer, such as `CMSampleBufferGetImageBuffer(sample)`. |
| `f` | `(bytes: Uint8Array, bytesPerRow: number, width: number, height: number) => R` | yes | What reads the bytes; its result is withPixelBytes's. |
| `plane` | `number` | no | The plane of a planar format; 0 when left out. |

### adoptPixelBuffer()

```ts title="ios.d.ts"
function adoptPixelBuffer(
  pixelBuffer: NSObject,
  plane?: number,
  access?: "read" | "readwrite",
): NativeBuffer;
```

A NativeBuffer of a CVPixelBuffer plane's bytes, uncopied: the pixel buffer is retained and locked until they're released, then unlocked. A camera frame can move to a worker, or with `"readwrite"` to JavaScript (`transferToArrayBuffer()`), without a copy. `withPixelBytes` is the form that copies.

The bytes are the plane's `bytesPerRow × height`. A read-only buffer's writes throw `InvalidStateError`, and so does `transferToArrayBuffer()`, since an ArrayBuffer is writable.

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `pixelBuffer` | `NSObject` | yes | A CVPixelBuffer, such as `CMSampleBufferGetImageBuffer(sample)`. |
| `plane` | `number` | no | The plane of a planar format; 0 when left out. |
| `access` | `"read" \| "readwrite"` | no | `"read"` (the default) locks it for reading, and `"readwrite"` for writing too. |

```ts title="adoptPixelBuffer.lucent.ts"
import { adoptPixelBuffer, type NSObject } from "lucent:ios";

// A frame's pixels, for JavaScript: no copy on the way.
function forJavaScript(pixelBuffer: NSObject): ArrayBuffer {
  return adoptPixelBuffer(pixelBuffer, 0, "readwrite").transferToArrayBuffer();
}
```

### nativeError()

```ts title="ios.d.ts"
function nativeError(error: Error): NSError | null;
```

The NSError `error` came from: what a throwing method, an `NSError**` out-parameter or a completion handler gave. Read its `domain`, `code` and `userInfo` as the SDK types them, rather than parsing `code` (`"NSCocoaErrorDomain:260"`). Null for an error Lucent or JavaScript made.

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `error` | `Error` | yes | A caught error. |

```ts title="nativeError.lucent.ts"
import { nativeError } from "lucent:ios";
import { FileManager, NSCocoaErrorDomain } from "lucent:ios/Foundation";

function exists(path: string): boolean {
  try {
    FileManager.default.attributesOfItem(path);
    return true;
  } catch (e) {
    const ns = nativeError(e as Error);
    // NSFileReadNoSuchFileError: the file isn't there.
    if (ns?.domain === NSCocoaErrorDomain && ns.code === 260n) return false;
    throw e;
  }
}
```

### onAppEvent()

```ts title="ios.d.ts"
function onAppEvent(
  event: AppEvent,
  listener: () => void,
  signal?: AbortSignal,
): () => void;
```

Calls `listener` each time the app posts `event`, until the returned function is called or `signal` aborts. It runs on the main thread, as UIKit posts it, so main-thread APIs work there without `main()`.

Lucent observes the notifications, so the app's delegate and other modules' stay as they are. What `listener` throws is logged, and the app goes on.

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `event` | `AppEvent` | yes | The notification, by name. |
| `listener` | `() => void` | yes | Called on the main thread each time it is posted. |
| `signal` | `AbortSignal` | no | Stops listening, as the returned function does. |

### onAppEvent()

```ts title="ios.d.ts"
function onAppEvent(
  event: "openURL",
  listener: (url: string, sourceApplication: string) => boolean,
  signal?: AbortSignal,
): () => void;
```

Calls `listener` with each URL the app is asked to open, and the bundle id of the app that asked (`""` when iOS doesn't say). It answers whether it opened the URL.

The URL comes from the app delegate, or the scene delegate in an app with scenes, which forwards it to Lucent. A URL that launched the app waits for the first listener. `listener` runs on the main thread while iOS waits for its answer.

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `event` | `"openURL"` | yes | `"openURL"`. |
| `listener` | `(url: string, sourceApplication: string) => boolean` | yes | Called with the URL and the asking app's bundle id. |
| `signal` | `AbortSignal` | no | Stops listening, as the returned function does. |

```ts title="onAppEvent.lucent.ts"
import { onAppEvent } from "lucent:ios";

function watchLinks(open: (path: string) => void): () => void {
  return onAppEvent("openURL", (url) => {
    if (!url.startsWith("myapp://")) return false;
    open(url.slice("myapp://".length));
    return true;
  });
}
```

### present()

```ts title="ios.d.ts"
function present<T>(
  build: (resolve: (value: T) => void, reject: (reason: Error) => void) => UIViewController,
  signal?: AbortSignal,
): Promise<T>;
```

Presents the view controller `build` returns from the scene the person is using (the top view controller of its key window). Resolves with the value given to `resolve`, or rejects with the error given to `reject`.

`build` runs on the main thread, like `main()`'s function. Make the view controller there, and call `resolve` or `reject` from its delegate or completion handler.

It settles once, and whatever settles it dismisses the view controller if it is still shown. It rejects with an `AbortError` when `signal` aborts, or when the person dismisses the view controller (swiping a sheet down). It does too when the view controller goes before settling, or when its scene disconnects.

It rejects with an `InvalidStateError` when no scene is in the foreground, or UIKit doesn't present it.

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `build` | `(resolve: (value: T) => void, reject: (reason: Error) => void) => UIViewController` | yes | Makes the view controller, on the main thread. |
| `signal` | `AbortSignal` | no | Dismisses it and rejects with an `AbortError`. |

### NSObject

### Out

```ts title="ios.d.ts"
class Out<T> {
  constructor();
  value: T | null;
}
```

What a method writes through a pointer (`CGFloat *`, `NSRange *`, `NSDate **`, `CFTypeRef *`): pass it, then read `value`. For a pointer the method also reads (a number or a struct), set `value` first.

### AsyncSequence

```ts title="ios.d.ts"
class AsyncSequence<T> {
  protected constructor();
  collect(f: (value: T) => void, signal?: AbortSignal): Promise<void>;
}
```

A Swift AsyncSequence, such as StoreKit's `Transaction.updates` or an `AsyncStream`, collected as Kotlin's Flow is. `collect` calls `f` with each element in order on its package's thread, and the sequence waits for each call. It settles when the sequence ends, rejecting with what the sequence or `f` throws.

Aborting `signal` cancels the iteration's task.
