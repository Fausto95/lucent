## lucent-sdk.lock.json

The SDKs a project's modules were read from and the SDK symbols its code uses. No machine paths.

`lucent sdk lock` writes it at the project's root, and `.lucent/sdk-usage.json` has the same shape. Schema: `https://lucent-lang.dev/schemas/sdk-lock.schema.json`.

| Field | Type | Always there | Meaning |
| --- | --- | --- | --- |
| `format` | `1` | yes |  |
| `targets` | `("ios" or "android")[]` | yes | The targets platform code was compiled for: a --frozen build needs each one's SDK |
| `modules` | `{ [name]: object }` | yes | \<platform\>/\<module\> → how the build read it |
| `modules.<name>.artifacts` | `string[]` | yes | The artifacts its schema was read from: \<id\>#\<content hash\> |
| `modules.<name>.schema` | `string` |  | Where the SDK cache keeps that schema: \<scope\>/\<entry\> |
| `symbols` | `object[]` | yes |  |
| `symbols[].platform` | `"ios" or "android"` | yes |  |
| `symbols[].module` | `string` | yes |  |
| `symbols[].owner` | `string` |  | The declaring type's Lucent name |
| `symbols[].kind` | `"type" or "constructor" or "method" or "property" or "function" or "constant"` | yes |  |
| `symbols[].name` | `string` | yes | The Lucent name; constructor for constructors |
| `symbols[].static` | `true` |  |  |
| `symbols[].symbol` | `string` |  | The native identity: swift:, objc:, c: or jvm: |
| `symbols[].signature` | `string` | yes |  |
| `symbols[].since` | `number or string` |  |  |
| `symbols[].deprecated` | `true` |  |  |
| `symbols[].cases` | `string[]` |  |  |
| `symbols[].roles` | `("call" or "new" or "get" or "set" or "implement")[]` |  |  |
