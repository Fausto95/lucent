Each helper has a native implementation, and a JavaScript one in `@lucent-lang/lucent/core` that tests run modules with ([Test a module](/docs/guides/test-a-module/)). This page documents both.

## Example

```ts title="measure.lucent.ts"
import { delay, error, errorCode, now } from "lucent:core";

export async function measure(task: string, signal?: AbortSignal): Promise<number> {
  if (task.length === 0) throw error("E_EMPTY", "Name the task to measure.");
  const start = now();
  await delay(10, signal);
  return now() - start;
}

export function codeOf(e: Error): string {
  return errorCode(e) ?? "unknown";
}
```

## Functions

### onDestroy()

```ts title="core.d.ts"
function onDestroy(hook: () => void): () => void;
```

Runs `hook` when this module's state ends: before a JavaScript reload initializes the module again, or when the app's JavaScript runtime goes, as Expo's `OnDestroy` does. A module's top-level code is its create hook. Stop there what module code started for this state and that a reload would leave running, such as an SDK observer.

Module state is the app's, whichever runtime started it. A second React Native instance shares it, and it ends only when the last one goes.

Hooks run in a turn of the module's code, the last registered first, while the module's state is still the one ending. What one throws goes to the platform log, and the others run.

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `hook` | `() => void` | yes | What to run when the module's state ends. |

```ts title="onDestroy.lucent.ts"
import { onDestroy } from "lucent:core";

let watching: (() => void) | undefined;
const stopWatching = onDestroy(() => watching?.());
```

### fromCallback()

```ts title="core.d.ts"
function fromCallback<T>(
  register: (resolve: (value: T) => void, reject: (reason: Error) => void) => (() => void) | void,
  signal?: AbortSignal,
): Promise<T>;
```

A promise of what a callback API reports once, such as a native listener. `register` starts listening at once, and may return the cleanup that stops it.

The first of `resolve`, `reject` and the signal aborting settles the promise, and later calls do nothing. `resolve` takes a value, not a promise: the compiler refuses a promise type.

The cleanup runs exactly once, inside the call that settles the promise, before anything awaiting it continues. If the promise settled during registration, it runs right after `register` returns. A cleanup that throws is reported as uncaught, and the promise keeps its outcome.

A throw from `register` rejects the promise. With a signal already aborted, the promise rejects with the signal's reason, and `register` is not called.

Called from another thread (inside `main()`, say), `resolve` and `reject` take effect on the thread `fromCallback` was called on, in the order they were called.

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `register` | `(resolve: (value: T) => void, reject: (reason: Error) => void) => (() => void) \| void` | yes | Starts listening with `resolve` and `reject`, and may return the cleanup. |
| `signal` | `AbortSignal` | no | Rejects the promise with its reason, and runs the cleanup. |

```ts title="fromCallback.lucent.ts"
import { fromCallback } from "lucent:core";

// Who waits for the next tick, as a native listener would hold it.
let waiting: ((tick: number) => void) | undefined;

export function tick(n: number): void {
  waiting?.(n);
}

export async function nextTick(signal?: AbortSignal): Promise<number> {
  return await fromCallback<number>((resolve) => {
    waiting = resolve;
    return () => {
      waiting = undefined;
    };
  }, signal);
}
```

### subscribe()

```ts title="core.d.ts"
function subscribe<T>(
  register: (
    next: (value: T) => void,
    end: () => void,
    fail: (error: Error) => void,
  ) => (() => void) | void,
  onValue: (value: T) => void,
  signal?: AbortSignal,
): Promise<void>;
```

Passes what a listener reports to `onValue` until the subscription ends, and resolves when it does. `register` starts listening at once, and may return the cleanup that stops it.

`next(value)` calls `onValue(value)` while the subscription is open, and does nothing after. The first of `end()`, `fail(error)`, `onValue` throwing and the signal aborting ends it. The promise then resolves (`end()`, or the signal: aborting is how the caller ends it) or rejects with the error.

The cleanup, a throw from `register` and calls from other threads behave as in `fromCallback`. With a signal already aborted, the promise resolves, and `register` is not called.

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `register` | `(
    next: (value: T) => void,
    end: () => void,
    fail: (error: Error) => void,
  ) => (() => void) \| void` | yes | Starts listening with `next`, `end` and `fail`, and may return the cleanup. |
| `onValue` | `(value: T) => void` | yes | Called with each value while the subscription is open. |
| `signal` | `AbortSignal` | no | Ends the subscription, and resolves the promise. |

### compute()

```ts title="core.d.ts"
function compute<T, R>(
  task: (input: T) => R,
  input: T,
  options?: ComputeOptions,
): Promise<Awaited<R>>;
```

Runs `task(input)` on a pool of worker threads, and resolves with its result on the thread that called `compute`. Several tasks run at once.

`task` is a function declared at the top level of a module, taking one parameter. The compiler checks that it uses no module state, no main-thread native code and nothing asynchronous (LUCENT3011). It checks that `input` and its result are data too (LUCENT3012).

`input` is copied when `compute` is called, so later changes by the caller don't reach the task. Objects reached twice are copied once, and cycles survive. The result comes back as it is.

A task that throws rejects the promise with its error. Aborting `signal` rejects it at once with the signal's reason, and a queued task never starts.

A running task stops at the next iteration of a loop in it, or in a module function it calls. Loops in closures, methods and generic functions, and native calls, run to their end first, and their result is dropped.

The pool holds a bounded number of waiting tasks: beyond it, `compute` rejects with a QuotaExceededError.

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `task` | `(input: T) => R` | yes | A function declared at the top level of a module, taking one parameter. |
| `input` | `T` | yes | Data, copied when `compute` is called. |
| `options` | `ComputeOptions` | no | `signal` cancels the task. |

```ts title="compute.lucent.ts"
import { compute } from "lucent:core";

function edgePositions(bytes: Uint8Array): number[] {
  const positions: number[] = [];
  for (let i = 1; i < bytes.length; i++)
    if (Math.abs(bytes[i]! - bytes[i - 1]!) > 40) positions.push(i);
  return positions;
}

export async function edges(bytes: Uint8Array, signal: AbortSignal): Promise<number[]> {
  return await compute(edgePositions, bytes, { signal });
}
```

## Classes

### EventEmitter

```ts title="core.d.ts"
class EventEmitter<Events extends { [name: string]: (...args: never[]) => void }> {
  constructor();
  addListener<K extends keyof Events & string>(name: K, listener: Events[K]): EventSubscription;
  emit<K extends keyof Events & string>(name: K, ...args: Parameters<Events[K]>): void;
  listenerCount(name: keyof Events & string): number;
  removeAllListeners(name?: keyof Events & string): void;
  onObserved(name: keyof Events & string, observer: (observed: boolean) => void): EventSubscription;
}
```

Events a module sends to its listeners, in Lucent and in JavaScript. `Events` names each event and its listener's signature, as Expo's `EventEmitter` does: `EventEmitter<{ progress: (percent: number) => void }>`.

`emit(name, ...args)` calls the event's listeners, in the order they were added; those added or removed while it runs take effect at the next emit. A listener's throw ends the emit and reaches its caller. In Lucent, an event's name is a string literal.

An EventEmitter crosses to JavaScript as the same object each time, with the same methods.

A JavaScript listener is a callback Lucent holds. During a synchronous call from JavaScript it runs at once. From anywhere else it is posted to the JS thread, with copies of its arguments.

Each JavaScript listener belongs to its runtime: a reload removes it, and `listenerCount` stops counting it. In JavaScript, naming an event that the type doesn't declare throws a TypeError.

```ts title="eventEmitter.lucent.ts"
import { EventEmitter } from "lucent:core";

export const downloads = new EventEmitter<{
  progress: (url: string, percent: number) => void;
  done: (url: string) => void;
}>();

export async function download(url: string): Promise<void> {
  for (let percent = 0; percent <= 100; percent += 10) downloads.emit("progress", url, percent);
  downloads.emit("done", url);
}
```

| Member | What it does |
| --- | --- |
| `constructor();` |  |
| `addListener<K extends keyof Events & string>(name: K, listener: Events[K]): EventSubscription;` | Adds `listener` to the event's listeners, last; the subscription removes it. |
| `emit<K extends keyof Events & string>(name: K, ...args: Parameters<Events[K]>): void;` | Calls each of the event's listeners with `args`. |
| `listenerCount(name: keyof Events & string): number;` | How many listeners the event has. |
| `removeAllListeners(name?: keyof Events & string): void;` | Removes the event's listeners, or every event's without a name. |
| `onObserved(name: keyof Events & string, observer: (observed: boolean) => void): EventSubscription;` | Calls `observer(true)` when the event gets its first listener, from Lucent or JavaScript, and `observer(false)` when its last one goes: removed, or taken by a reload. It is called at once with `true` if the event has listeners already. The subscription stops it. Use it to start the native source behind an event only while someone listens. |

### JSValue

```ts title="core.d.ts"
class JSValue {
  private constructor();
  private readonly opaque: never;
}
```

A value JavaScript gave, which Lucent code holds without looking inside: another library's object, a callback to hand back, any value. Lucent code stores it, passes it on and returns it, and JavaScript gets the same value back. An object keeps its identity, a function stays callable, a primitive stays itself.

Nothing else reads it: comparing, converting, testing or `typeof` one is refused. So are writing it as JSON, keying a `Map` or `Set` with it, and handing it to a compute task. An optional one (`JSValue | undefined`) is absent for JavaScript's `undefined` and `null`, as `??` sees them.

The runtime's host holds the value until the last Lucent reference goes. One held across a reload is refused when it goes back to JavaScript.

```ts title="jSValue.lucent.ts"
import type { JSValue } from "lucent:core";

export class Player {
  constructor(readonly source: JSValue) {}
}

export function play(source: JSValue): Player {
  return new Player(source);
}
```

### NativeBuffer

```ts title="core.d.ts"
class NativeBuffer {
  private constructor();
  static allocate(size: number): NativeBuffer;
  static from(bytes: Uint8Array): NativeBuffer;
  static stats(): NativeBufferStats;
  readonly byteLength: number;
  withRead<R>(read: (bytes: ByteSpan) => R): R;
  withWrite<R>(write: (bytes: MutableByteSpan) => R): R;
  withReadAs<A extends ViewedArray, R>(
    type: ViewedArrayType<A>,
    read: (values: TypedSpan<A>) => R,
  ): R;
  withWriteAs<A extends ViewedArray, R>(
    type: ViewedArrayType<A>,
    write: (values: MutableTypedSpan<A>) => R,
  ): R;
  toUint8Array(): Uint8Array;
  transfer(): NativeBuffer;
  transferToArrayBuffer(): ArrayBuffer;
  close(): void;
  handle(): NativeHandle;
  [Symbol.dispose](): void;
}
```

Bytes native code owns, handed to compute tasks and JavaScript without copying them. A `Uint8Array` is copied whenever it crosses, while a NativeBuffer moves.

The bytes are reached through a borrow, for the length of one call. `withRead` lends them to its callback as a `ByteSpan`, and `withWrite` as a `MutableByteSpan`. Reads share the buffer, while a write needs it to itself.

`withReadAs` and `withWriteAs` lend them as another typed array's elements: `buffer.withReadAs(Float32Array, (samples) => …)`.

A borrow that conflicts with one in progress throws an InvalidStateError ("NativeBuffer is borrowed") at once. That is a write inside a read, or a close or transfer inside either.

The callback is a function literal or the name of a function, and its span stays inside it. Returning the span, storing it, keeping it in a closure or a callee, or holding it across `await` is refused (LUCENT3030).

`transfer()` moves the bytes to a new buffer, uncopied. Every reference to the old one then throws an InvalidStateError ("NativeBuffer was transferred"), and closing it does nothing. A use the compiler can tell follows a move is refused (LUCENT3031).

Passing a buffer to `compute`, alone or inside the input, moves it the same way, and a task's buffer comes back as it is. A buffer borrowed at the time doesn't move: the promise rejects.

After `close()`, or the end of its `using` block, the buffer throws an InvalidStateError ("NativeBuffer is closed"). Copies are explicit: `NativeBuffer.from(bytes)` and `toUint8Array()`, which `NativeBuffer.stats()` counts.

JavaScript sees a buffer as an opaque object with the same methods. Its borrows lend it a copy of the bytes, copied back after `withWrite`, so JavaScript never holds memory a worker may be writing.

```ts title="nativeBuffer.lucent.ts"
import { compute, NativeBuffer } from "lucent:core";

function scan(buffer: NativeBuffer): number {
  using owned = buffer;
  return owned.withRead((bytes) => {
    let total = 0;
    for (let i = 0; i < bytes.length; i++) total += bytes[i]!;
    return total;
  });
}

export async function sample(): Promise<number> {
  const buffer = NativeBuffer.allocate(4096);
  buffer.withWrite((bytes) => bytes.fill(7));
  return await compute(scan, buffer.transfer());
}
```

| Member | What it does |
| --- | --- |
| `static allocate(size: number): NativeBuffer;` | A buffer of `size` zeroed bytes: a RangeError unless `size` is a whole number from 0. |
| `static from(bytes: Uint8Array): NativeBuffer;` | A new buffer holding a copy of `bytes`. |
| `static stats(): NativeBufferStats;` | What every buffer has done since the app started. |
| `readonly byteLength: number;` | How many bytes it holds: 0 once closed or transferred. |
| `withRead<R>(read: (bytes: ByteSpan) => R): R;` | Calls `read` with the bytes, while no one writes them, and returns what it returns. |
| `withWrite<R>(write: (bytes: MutableByteSpan) => R): R;` | Calls `write` with the bytes, while nothing else borrows them, and returns what it returns. A read-only buffer (a frame adopted for reading) throws InvalidStateError. |
| `withReadAs<A extends ViewedArray, R>(type: ViewedArrayType<A>, read: (values: TypedSpan<A>) => R): R;` | Calls `read` with the bytes read as `type`'s elements, little-endian, as `new Float32Array(buffer)` reads them. Bytes that aren't a whole number of elements throw a RangeError. |
| `withWriteAs<A extends ViewedArray, R>(type: ViewedArrayType<A>, write: (values: MutableTypedSpan<A>) => R): R;` | Calls `write` with the bytes as `type`'s elements, as `withWrite` and `withReadAs` do. |
| `toUint8Array(): Uint8Array;` | A copy of the bytes, independent of the buffer from then on. |
| `transfer(): NativeBuffer;` | Moves the bytes, uncopied, to a new buffer: every reference to this one refuses them from now on. |
| `transferToArrayBuffer(): ArrayBuffer;` | Moves the bytes, uncopied, into an `ArrayBuffer`. Every reference to this buffer refuses them from now on, and the ArrayBuffer releases them as the buffer would have. Returned to JavaScript, it is the same bytes. A borrowed buffer does not move (an InvalidStateError), nor does a read-only one, since an ArrayBuffer is writable. |
| `close(): void;` | Releases the bytes. Closing a closed or transferred buffer does nothing. |
| `handle(): NativeHandle;` | A handle of the bytes' address, for native code that takes one (a library JavaScript passes the pointer to). It borrows the bytes for read until it is released: reads go on, while writes, `transfer()` and `close()` throw an InvalidStateError. An empty buffer has no address (a RangeError). |
| `[Symbol.dispose](): void;` |  |

### NativeHandle

```ts title="core.d.ts"
class NativeHandle {

  readonly released: boolean;

```

An address native code takes, held valid until released, as VisionCamera's `NativeBuffer` gives one to Skia. JavaScript gets the same object, and passes `pointer` to the library that reads it.

### Channel

```ts title="core.d.ts"
class Channel<T> {
  constructor(policy: ChannelPolicy, capacity?: number);
  send(value: T): boolean;
  receive(): Promise<T | undefined>;
  [Symbol.asyncIterator](): AsyncIterator<T>;
  subscribe(onValue: (value: T) => void): EventSubscription;
  close(): boolean;
  readonly closed: boolean;
  stats(): ChannelStats;
}
```

Values from a producer to a consumer, which may run on different threads. A compute task sends results as it goes, and module code receives them. A send never waits for the consumer; when the consumer falls behind, the channel's policy decides what waits.

A value is copied when it is sent, as a compute task's input is, so the consumer has its own; a `NativeBuffer` moves instead. A value the channel drops, or that is never received, is released: a `NativeBuffer` is closed.

```ts title="channel.lucent.ts"
import { Channel, compute } from "lucent:core";

function scan(input: { rows: number[][]; progress: Channel<number> }): number {
  for (let i = 0; i < input.rows.length; i++) input.progress.send(i + 1);
  input.progress.close();
  return input.rows.length;
}

export async function scanAll(rows: number[][]): Promise<number> {
  const progress = new Channel<number>("latest");
  const done = compute(scan, { rows, progress });
  for (let n = await progress.receive(); n !== undefined; n = await progress.receive())
    console.log(`row ${n}`);
  return await done;
}
```

| Member | What it does |
| --- | --- |
| `constructor(policy: ChannelPolicy, capacity?: number);` |  |
| `send(value: T): boolean;` | Sends a copy of `value` (a `NativeBuffer` moves), without waiting. False if refused: the channel is closed, or lossless and full; the value is then left as it was. |
| `receive(): Promise<T \| undefined>;` | The next value: at once if one waits, else when one is sent; `undefined` once the channel is closed and every value was received. |
| `[Symbol.asyncIterator](): AsyncIterator<T>;` | `for await (const value of channel)`: each value it receives, until `receive()` gives `undefined`, once it is closed and every value was received. Leaving the loop early leaves the channel as it is. |
| `subscribe(onValue: (value: T) => void): EventSubscription;` | Calls `onValue` with each value as it comes, one at a time, where this code runs. The next is received once `onValue` returns, so the policy still decides what waits meanwhile. It goes on until the channel is closed and every value was received, or until the subscription is removed. After that, values wait for the next receive. What `onValue` throws is reported, and the next value comes. |
| `close(): boolean;` | Refuses sends from now on; what waits can still be received. False if it was closed already. |
| `readonly closed: boolean;` | Whether it is closed. |
| `stats(): ChannelStats;` | What it has done so far, and how many values wait now. |

### ChannelPolicy

```ts title="core.d.ts"
type ChannelPolicy = "lossless" | "latest" | "drop";
```

What a channel does when its consumer has no room for a value: `"lossless"` refuses the send, `"latest"` keeps only the newest value, `"drop"` drops the oldest.

### ChannelStats
