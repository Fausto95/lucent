The Android SDK itself is imported from `lucent:android/<package>`, typed from the installed SDK and the app's Gradle libraries. [Android SDK bindings](/docs/api/android-sdk/) gives the rules, and [Find an SDK class](/docs/guides/find-an-sdk-class/) looks one up.

## Example

```ts title="vibrate.lucent.ts"
import { PLATFORM } from "lucent:platform";
import { Vibrator, VibratorManager } from "lucent:android/android.os";
import { appContext, available } from "lucent:android";

export function vibrate(): void {
  if (PLATFORM === "android") {
    const context = appContext();
    const vibrator = available("android", 31)
      ? context.getSystemService(VibratorManager)?.defaultVibrator
      : context.getSystemService(Vibrator);
    vibrator?.vibrate(20n);
  }
}
```

### errorOf()

```ts title="android.d.ts"
function errorOf(throwable: Throwable): Error;
```

The Error Lucent makes of `throwable` when a call throws it. Its message is the exception's (or its class name, without one), and its `code` is the class name (`java.lang.IllegalStateException`). An exception carrying a Lucent error, one a Lucent suspend function ended a Kotlin call with, gives that error.

For an adapter whose callback API reports failure with a Throwable, `reject(errorOf(e))` rejects as the call would have thrown.

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `throwable` | `Throwable` | yes | The exception, such as one a callback received. |

### nativeError()

```ts title="android.d.ts"
function nativeError(error: Error): Throwable | null;
```

The Java exception `error` came from: what a call threw, or a callback gave `errorOf`. Test its class with `instanceof` and read its members, rather than matching `code`. Null for an error Lucent or JavaScript made.

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `error` | `Error` | yes | A caught error. |

```ts title="nativeError.lucent.ts"
import { nativeError } from "lucent:android";
import { FileInputStream, FileNotFoundException } from "lucent:android/java.io";

function open(path: string): FileInputStream | null {
  try {
    return new FileInputStream(path);
  } catch (e) {
    if (nativeError(e as Error) instanceof FileNotFoundException) return null;
    throw e;
  }
}
```

### currentActivity()

```ts title="android.d.ts"
function currentActivity(): Activity | null;
```

The Activity in front: the one last created, started or resumed and not destroyed, or null (before the first, between two, after the last). Lucent holds Activities weakly: use this one now, on the main thread (inside `main()`), and ask again later rather than keeping it.

### startActivityForResult()

```ts title="android.d.ts"
function startActivityForResult(
  intent: Intent,
  signal?: AbortSignal,
): Promise<Instrumentation_ActivityResult>;
```

Starts `intent` from the Activity in front, and resolves with its result (`getResultCode()`, `getResultData()`). The request survives the app's Activity being recreated meanwhile.

It rejects with `ERR_NO_ACTIVITY` without an Activity, and with `ERR_ACTIVITY_NOT_FOUND` when no app handles the intent. It rejects with the signal's reason if it aborts first, and drops the answer if it comes. Lucent closes what it started when Android lets it.

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `intent` | `Intent` | yes | What to start. |
| `signal` | `AbortSignal` | no | Rejects with its reason; a later answer is dropped. |

### requestPermissions()

```ts title="android.d.ts"
function requestPermissions(
  permissions: string[],
  signal?: AbortSignal,
): Promise<boolean[]>;
```

Asks for runtime permissions (`"android.permission.CAMERA"`), and resolves with whether each was granted, in order. Requests wait for the one before them, as Android asks one at a time. It rejects like `startActivityForResult`.

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `permissions` | `string[]` | yes | Their names, such as `"android.permission.CAMERA"`. |
| `signal` | `AbortSignal` | no | Rejects with its reason; a later answer is dropped. |

### onActivityEvent()

```ts title="android.d.ts"
function onActivityEvent(
  event: ActivityEvent,
  handler: (activity: Activity, intent: Intent | null) => void,
): () => void;
```

Runs `handler` after each `event` of the app's Activities, with the Activity (and the intent, for "newIntent"), in a turn of the calling context. Returns the function that stops it.

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `event` | `ActivityEvent` | yes | The lifecycle event, or `"newIntent"`. |
| `handler` | `(activity: Activity, intent: Intent \| null) => void` | yes | Called with the Activity, and the intent for `"newIntent"`. |
