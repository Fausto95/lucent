Lucent supports the current and the previous stable releases of React Native and Expo, and `lucent create` starts an app on the newest. A prerelease lane beside them is where the example apps run. When a stable release ships, it joins, the oldest leaves, and the lane moves to the next release candidate.

|  | Supported |
| --- | --- |
| React Native | 0\.85 to 0.87, New Architecture (0.85 is Expo SDK 56's); 0.88's release candidates on the prerelease lane |
| Expo | SDK 56 and 57, in a development build; the SDK 58 preview on the prerelease lane |
| Node | 22\.12 or later |
| JDK, for Android builds | 17 to 21 |
| Android | API 24 and later; newer APIs need an `available` check |
| iOS | 15\.1 and later; APIs newer than the app's deployment target need an `available` check |
| TypeScript | 5\.9.3, which the package brings; modules are checked against `es2024` and `esnext.disposable` and `esnext.collection` |
| Xcode, Android SDK and NDK | the versions your React Native version needs |

## Operating systems

| Machine | What works |
| --- | --- |
| macOS | Everything. iOS needs macOS: Xcode types iOS code and builds it, and nothing else does. |
| Linux | Android builds and checks. iOS code is untyped and isn't compiled: `lucent build` and `lucent check` skip iOS with a warning. Lucent can't import iOS types from another machine, so type errors in iOS code show only on a Mac. |
| Windows | Unsupported and untested. Use WSL, which is a Linux machine: Android only. |

`lucent doctor` checks these on your machine and names the lane of the app's React Native and Expo releases. This table is generated from the same numbers.

Tested on the iOS simulator (Xcode 27) and the Android emulator, in the example apps, bare and Expo, which are on the prerelease lane. CI compiles Lucent's React Native code against each release of the window, and builds and runs fresh bare and Expo apps on each nightly. Not yet on physical devices ([roadmap](/docs/releases/roadmap/)).
