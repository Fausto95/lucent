A module that type-checks, and uses only what the Language pages list, behaves as the same code does in JavaScript. Each difference in the sections below is deliberate, and its row says why. Any [known gaps](/docs/api/language/differences/#known-gaps) at the end aren't: Lucent should refuse that code or match JavaScript.

Each e2e case is a module in `packages/compiler/test/e2e/cases/`, run natively and as JavaScript, whose outputs must match. A case therefore tests the behavior around a difference, never the difference itself.

## Arrays and collections

| JavaScript | Lucent | Why | e2e case |
| --- | --- | --- | --- |
| `arr[i] = v` past the end leaves holes. | Throws a `RangeError`, whatever the element type. Append with `push`, or assign at `length`. | A Lucent array has no holes: each element holds a value of its type. | `assignment-order` |
| `arr[-1] = v` and `arr[1.5] = v` add a property. | Throws a `RangeError`. | A Lucent array has elements only, no other properties. | None |
| Setting a larger `length` leaves holes. | Throws a `RangeError`, whatever the element type. | A Lucent array has no holes. | `collections` |
| `new Array(n)` has `n` holes. | Refused unless a `.fill(v)` follows it ([LUCENT1003](/docs/api/diagnostics/#lucent1003)). Write `new Array(n).fill(v)` or `Array.from({ length: n }, (_, i) => …)`. | A Lucent array has no holes, and its element type may have no `undefined`. | `collections` |
| `x!` does nothing at run time. | Throws a `TypeError` when `x` is `undefined` or `null`, such as an index out of range. | The assertion is checked, so a wrong one fails where it's made. | None |
| `x as T` does nothing at run time. | Taking a member out of a union, such as `x as number` on a `string \| number`, checks the value: another member throws a `TypeError`. | A native union holds one member's layout, so the value can't be read as another. | None |
| `map.keys()`, `values()` and `entries()`, and the same methods of arrays, sets and typed arrays, return iterators. | They return arrays, holding the contents at the time of the call. | An array serves everywhere these iterators are read: `for…of`, spread and `Array.from`. | `collections`, `typed-arrays` |
| Garbage collection frees cycles. | Reference counting never frees a cycle. Break it by clearing a field, or hold one side in a `WeakRef` ([Memory](/docs/api/language/memory/#cycles-leak)). | Lucent counts references, and no collector runs. | None |
| A `WeakRef`'s target lives until the garbage collector runs, so `deref()` may still return it after the last other reference goes. | The target is freed with its last strong reference, and `deref()` returns `undefined` at once. | Lucent counts references, so a target goes when its count reaches zero. | `weak-refs` |
| A `WeakMap` or `WeakSet` entry lives until the garbage collector runs, and a value that holds only its own key frees with it. | An entry goes, its value with it, with its key's last strong reference, at once. A value that holds its own key keeps it, and the entry. | Lucent counts references: the key's last reference drops its entries, and nothing traces through a value to its key. | `weak-collections` |
| A `FinalizationRegistry`'s cleanup runs some time after the garbage collector frees the target, or never. | It runs soon after the target's last strong reference goes, as a job, every time. | Lucent counts references, so a target goes when its count reaches zero. | `finalization` |
| Deep recursion throws a `RangeError` at the engine's limit. | It throws a `RangeError` too, when the native stack is nearly full: how deep that is depends on the thread's stack and the frames' sizes. | Lucent code runs on the native stack, which each call checks. | `recursion-limit` |

## Objects

| JavaScript | Lucent | Why | e2e case |
| --- | --- | --- | --- |
| An object's keys come in the order they were added. | An object type's fields have one fixed order, which `JSON.stringify` and the objects JavaScript receives follow. Use a record where order matters. | Objects of one type share one native layout. | `object-spread`, `json` |
| `Object.keys(obj)`, `for…in` and `"key" in obj` see the properties an object has. | On an object type they're refused ([LUCENT1003](/docs/api/diagnostics/#lucent1003), `LUCENT1009`, `LUCENT1002`). They work on records. | An object's native layout records neither which optional fields are set nor their order. | `object-keys` |
| `{ b: undefined }` has a key `b`. | An optional field holding `undefined` is unset: `JSON.stringify` and the boundary leave it out, and spreading skips it. | A native field is set or unset, with no third state. | `object-spread`, `absent-results` |

## Comparisons

| JavaScript | Lucent | Why | e2e case |
| --- | --- | --- | --- |
| `==` converts a number, string, boolean, bigint or object first, so `1 == "1"`. | Refused ([LUCENT1002](/docs/api/diagnostics/#lucent1002)). Compare with `===` after converting. | Lucent compiles `==` only where no conversion is needed: between values of one kind, or with `null` or `undefined` on one side. | `mixed-equality` |
| Functions compare by reference. | Comparing functions is refused, by `===`, `indexOf` or `includes` ([LUCENT1002](/docs/api/diagnostics/#lucent1002)), or as `Map` keys and `Set` elements ([LUCENT2002](/docs/api/diagnostics/#lucent2002)). | A function value has no stable identity in native code. | `function-values` |
| Tuples are arrays, compared by reference. | Tuples are values: `===` compares their elements. | A tuple is a fixed-size value in native code, not an array. | None |
| Two `subarray()` views of one range are different objects. | They are one view: `===`, `indexOf`, and `Map` and `Set` keys compare a view's buffer and range. | A view is a buffer and a range, with no identity of its own. | `reference-identity` |

## Strings, JSON and dates

| JavaScript | Lucent | Why | e2e case |
| --- | --- | --- | --- |
| `console.log(obj)` shows the object's structure. | Prints `String(obj)`. | The platform log takes a line of text. | `object-strings` |
| `str.split(regexp)` inserts `undefined` for a capture group that didn't match. | Inserts `""`. | The result's type is `string[]`. | `regexps` |
| `JSON.parse` returns whatever the text holds. | The text must match the target type. A mismatch throws a `TypeError` naming the path: `JSON.parse: expected a number at .items[2].price, got a string`. | The value is built in its type's native layout. | `json` |
| `JSON.stringify` of parsed data keeps the text's key order. | Keys follow the declared type's order. | An object type's fields have one order, the declared one. | `json` |
| `date.toString()` names the time zone in some engines. | Gives `Mon Jul 22 2019 15:51:50 GMT-0700`, as Hermes does. The `toLocale…` methods are refused. | Lucent follows React Native's engine, and has no `Intl` for locale formats. | `dates` |
| `new TextDecoder(label)` decodes the encoding the label names: UTF-16, Latin-1 and others. | Decodes UTF-8 only. Another encoding's label is [LUCENT1003](/docs/api/diagnostics/#lucent1003) when written in the call, and a `RangeError` when computed. | UTF-8 is what code shared between platforms reads. Decode another encoding with the platform's API. | `text-encoding` |

## The boundary

| JavaScript | Lucent | Why | e2e case |
| --- | --- | --- | --- |
| Type annotations are erased: any value reaches a function. | Each argument from JavaScript is checked against its declared type, and a mismatch throws a `TypeError` before the code runs ([The boundary](/docs/api/language/boundary/#when-a-value-doesnt-match)). That includes `null` where `undefined` is declared, or the other way round, in an element, a callback's result or a promise's value too. | A native value needs the declared layout. | `null-or-undefined`, `null-undefined-nested` |
| A `RegExp` passed to a function is the same object, with its `lastIndex`. | It crosses as a new `RegExp` with the same source and flags, and `lastIndex` back at 0. | A regular expression's state lives in native code. | None |
| An exported `let` holding an object is the module's object. | JavaScript reads the binding live, but gets a copy of each object, array, map or set the module assigns. Changes the module makes inside that value don't reach JavaScript ([Modules](/docs/api/language/modules/#exports)). | The value is copied at the boundary like any other. | `exported-variables` |
| An `EventEmitter` takes any event name. | From JavaScript, an `EventEmitter` from Lucent takes only the events its type declares: another name throws a `TypeError`. | Native code numbers the events when it compiles, so a name the type lacks has nowhere to keep its listeners. | `events` |
| Arrays and objects passed to other code are shared. | Copied at the boundary; inside Lucent they're shared. | JavaScript objects belong to the JS thread, and Lucent code runs on others. | `reference-identity` |
| A typed array, `DataView` or `ArrayBuffer` passed to other code is shared. | Copied at the boundary. A synchronous function that only reads one reads JavaScript's bytes in place while it runs, so JavaScript's writes meanwhile show. Inside Lucent they're shared. | The same as for arrays and objects. Bytes a call only reads need no copy: nothing holds them once it returns. | `array-buffers`, `borrowed-bytes`, `typed-arrays` |
| Code can read any value it is given. | A `JSValue` is a JavaScript value Lucent holds without reading. It is stored and handed back as the same value; comparing, converting or testing one is refused. | JavaScript's values live on the JS thread; Lucent holds a reference to one, which only JavaScript can read. | `opaque-values` |
| `Date` objects passed to other code are shared. | Copied at the boundary; inside Lucent they're shared. | The same as for arrays and objects. | `dates` |
| A function JavaScript passes returns its value whenever it's called. | Called off the JS thread, it's posted there, so it must return `void` or a `Promise`. | Lucent code never waits for the JS thread. | `async` |
| A class instance has its fields as own properties. | JavaScript sees public fields as accessors on the prototype, a `readonly` one without a setter, and no other members. `Object.keys` and `JSON.stringify` there see no fields. | The instance's fields live in native code, behind one JavaScript object. | `classes` |
| A class's `[Symbol.dispose]()` can be called from JavaScript. | JavaScript doesn't see the symbol-keyed members of a Lucent class: give a class JavaScript should close a `close()` method too. | Lucent gives JavaScript a class's members by name, and a symbol has none. Hermes has no `Symbol.dispose` either. | `using` |

## Errors and cancellation

| JavaScript | Lucent | Why | e2e case |
| --- | --- | --- | --- |
| `atob` and `btoa` throw a `DOMException` named `InvalidCharacterError`. | Throw an `Error` of that name, with Node's message. `e.name` reads the same, and `DOMException` isn't declared. | Lucent has no `DOMException`. | `base64` |
| `crypto.getRandomValues` throws a `QuotaExceededError` `DOMException` past 65536 bytes, and a `TypeMismatchError` for an array of floats. | Throws an `Error` named `QuotaExceededError`, with Node's message. An array of floats is [LUCENT1003](/docs/api/diagnostics/#lucent1003). | Lucent has no `DOMException`, and knows each array's type when it compiles. | `random-values` |
| `error.stack` is a string. | `undefined` in Lucent code, unless the error came from JavaScript. JavaScript receives a `stack` whose first frame is the Lucent one. | Native code records the site where it made an error, not a stack. | `errors` |
| `new Error(message, { cause })` keeps any value as the cause. | Keeps a cause that is an `Error`, and JavaScript gets it with the error. Another is refused ([LUCENT1003](/docs/api/diagnostics/#lucent1003)), and left out when JavaScript's error crosses to Lucent. | A Lucent error's cause is an error, as a caught value is. | `errors`, `error-cause` |
| `abort()` without a reason gives an `AbortError` whose message depends on the engine. | `AbortError: signal is aborted without reason`, as in React Native and browsers. | One message on both platforms. Node says `This operation was aborted`. | `abort`, `listeners` |
| `for await` over a channel takes a value from its async iterator, a few microtasks after the value comes. | Each value a microtask after `receive()` gives it, so other promise callbacks interleave with the loop in another order. | The loop awaits `receive()` itself, with no async iterator between them. | `for-await` |
| A generator's `yield` gives `undefined` after a `next()` without a value, and so does `next()` once the generator's result was reported. | Where `TNext` or `TReturn` leaves `undefined` out, Lucent gives the type's default: `0`, `""`, `false` or empty. An object throws a `TypeError`. | The value has the declared type, as an unassigned field does, and that type has no `undefined`. | `generator-values` |
| An async generator's `yield` awaits its value before its `next()` promise settles. | The promise settles with the value at once, a microtask sooner, so other promise callbacks interleave in another order. | A Lucent value is never a promise to adopt: there is nothing to await. | `async-generators` |
| The `AggregateError` that `Promise.any` rejects with has a message that depends on the engine. | `All promises were rejected`, as in V8. | One message on both platforms. | `promise-combinators` |
| An abort reason can be any value. | A reason from JavaScript becomes an error, with `String(reason)` as its message when it isn't an object. `abort()` in Lucent takes an `Error`. | Lucent's errors are `Error` objects. | `abort` |
| `resolve(promise)` in a promise executor adopts the promise. | `resolve` takes a value. Passing a promise fails, in `new Promise` with [LUCENT2002](/docs/api/diagnostics/#lucent2002) and in `fromCallback` with [LUCENT1007](/docs/api/diagnostics/#lucent1007). Await the promise, and resolve with its value. | A promise settles once, with a value of its type. | `listeners` |
| `await` on an object without a `then` method gives the object. | `await` on an SDK object is refused ([LUCENT1010](/docs/api/diagnostics/#lucent1010)). Adapt its completion listener with `fromCallback`. | Lucent never picks an SDK object's completion API by its name. | None |
| An error object that crosses to and from JavaScript is the same object, with all its fields. | An instance of an error class an export's types reach crosses as itself, so `instanceof` holds. Any other error crosses as a new `Error`, `TypeError`, `RangeError` or `SyntaxError` made from its `name`, `message`, `code` and stack ([The boundary](/docs/api/language/boundary/#errors)). The same error returned twice gives two objects, and a JavaScript error passed in and back loses its other fields. | Only a class JavaScript can see has a JavaScript class that keeps an instance's identity. | `errors`, `exported-errors` |
| JavaScript code can throw any value. | A value a JavaScript callback throws that isn't an `Error` reaches Lucent code as an `Error`. An object's string `name` and `message` are kept, and any other value becomes the message, as `String(value)`. | Lucent code catches errors only. | None |
| An error's `name` and `message` hold any value, and `Object.prototype.toString` of one gives `[object Error]`. | From JavaScript, `name` and `message` take strings only, or throw a `TypeError`. `Object.prototype.toString` of an instance of a Lucent error class gives `[object Object]`. | They are native strings, and the instance only inherits `Error.prototype`. | None |
| An error no code can catch, such as a cleanup's, reaches the host's error handler. | It's written to the platform log (logcat, the unified log) and to stderr. | Native code has no JavaScript error handler to call. | None |

## Classes and variables

| JavaScript | Lucent | Why | e2e case |
| --- | --- | --- | --- |
| A field read before it's assigned, such as a subclass field read from a base constructor, is `undefined`. | A number, string, boolean, tuple, array, map, set, record or typed array reads its default: `0`, `""`, `false` or empty. An object or class reads as unset: using it throws a `TypeError`, through `?.` too. | A field holds a native value from the start. | `unassigned-fields` |
| Any object with the right members fits an interface. | Only classes that declare `implements` fit one, and object literals of an interface of properties alone. A plain JavaScript object is refused at the boundary with a `TypeError`. | An interface with methods is a native base class, which only declared classes derive from. | `interfaces`, `interfaces-structural` |
| Assigning a static field a class inherits gives the subclass its own. | From JavaScript, it writes the base class's field, which the subclass shares. | A static field is one native variable, on the class that declares it. | `exported-statics` |

## Known gaps

None known: code that compiles does what JavaScript does, or differs as the tables above say.
